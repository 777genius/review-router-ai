# ReviewRouter product concept video

A self-contained Remotion composition for a **concept preview**, not a recording of the live product. It depicts the intended onboarding flow, review, and an illustrative insights screen. This original cut was based on an older checkout; its planned-feature labels reflect that checkout. Current main now implements OpenCodeReview, usage, and statistics with rollout and data-coverage limits. Verify the target deployment before using the video as a product demo.

The benchmark panel compares OpenCodeReview and Claude Code on Claude 4.6 Opus in the authors' AACR-Bench study: 385K vs. 5,664K average tokens and 1:23 vs. 13:06 average time. Results depend on model, task, and setup. It is not a benchmark of ReviewRouter. Source: https://arxiv.org/abs/2608.09290. Findings and usage figures in the insights scene are invented sample data.

## Work on the video

Requires Node.js, npm, and a supported Remotion browser. Install the exact locked dependencies and open Studio:

```sh
npm ci
npm run studio
```

Render the 1920×1080, 30 fps, 45.2-second H.264 video:

```sh
npm run render
```

The output is written to `out/`, which is ignored by Git. The scene timings are in `src/video.tsx`. All visual animation derives from frame numbers so the render remains deterministic.

`public/music.m4a` is an original synthetic instrumental bed generated by `scripts/generate-music.py` and encoded with FFmpeg. The logo and provider icons are copies of the project's existing public assets. Check [Remotion licensing](https://www.remotion.dev/docs/license/pricing) for the organization before publishing.

## Real frontend cut

`ReviewRouterReal` is the shorter 25.8-second edit. Render with `npm run render:real`. It animates captured interface states, cursor movements and camera moves; it does not connect an account or mutate a repository.

- Sign-in is a crop of the publicly accessible sign-in page on reviewrouter.org, captured without signing in.
- Provider choices are the actual `ProviderSecretSetupChooser` component from `apps/web`, mounted in the isolated `capture/` harness with synthetic guidance. The visible heading and “and more” line are presentation additions; the component is cropped to its real tabs.
- The repository screen mounts the actual `RepositoryLiveSearch`, `RepositorySetupDisclosureToggle`, badges and source icon. The surrounding rows and opened description are a presentation fixture based on the page markup, with invented repository names and setup states. It is not a screen recording of an authenticated dashboard.
- The pull-request finding and insights are illustrations. The planned-integration label reflects an older checkout; current main implements OpenCodeReview, subject to deployment availability. The cited benchmark is not a measurement of ReviewRouter.

To refresh the isolated local capture view, run `npm run capture:studio` and open `http://127.0.0.1:4777/?scene=providers` or `?scene=repos`. Captures used by the composition are under `public/captures`; recapturing the public sign-in page and the before/after component states requires a browser. Never use credentials, real private repositories or real setup actions for this demo.

## Updated product cut

`ReviewRouterV3` is the 32.1-second edit. It uses the current main-branch provider roster (Codex, Claude Code, MiMo Token Plan, OpenRouter and Kimi Code) and the repository's provider marks from `8d697434ad220dfd3e580b190e311726aa8366ed`. Render with `npx remotion render src/index.ts ReviewRouterV3 out/reviewrouter-v3.mp4 --codec=h264 --concurrency=2`.

The repository setup frames use real local search and setup controls plus a synthetic four-step presentation fixture. They show the workflow's Create setup PR, Merge setup PR, Enable review and Ready sequence; the animation does not perform these operations. The GitHub marks are recoloured white in the capture for contrast. The review comment and the statistics values are illustrative. Real usage coverage varies by deployment and provider.

The current main-branch README and capabilities document describe OpenCodeReview as the default review path, and Statistics and Usage as implemented with deployment and data-coverage limits. That supersedes the older local-checkout status described above, but does not establish that every workspace has completed rollout. The benchmark remains the upstream OpenCodeReview study, not a ReviewRouter measurement. The video describes the ReviewRouter service as free; AI provider subscriptions and API usage may still be charged separately.

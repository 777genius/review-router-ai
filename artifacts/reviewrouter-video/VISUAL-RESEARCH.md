# Как поднять качество ролика ReviewRouter

Исходная версия для сравнения: `out/reviewrouter-v6.mp4` (1920×1080, 30 fps, 27,05 с). Этот ресерч не меняет V6.

## Что видно в текущем V6

- Экран за экраном использует почти одинаковое появление: общий `Panel` с fade, вертикальным сдвигом и scale. Из-за повторения переходы не поддерживают смысл действий.
- Отступы задаются отдельно для сцен: intro `left: 150`, providers `inset: 145px 80px`, repositories `145px 95px`, review `125px 105px`, stats `115px 105px`. Общей сетки для заголовков, контента и подписи нет; поэтому сцены визуально «прыгают».
- Видеоканвас наследует Inter, а продукт загружает Space Grotesk и JetBrains Mono. Отсюда расхождение в характере интерфейса и метриках текста.
- Некоторые подписи и элементы реального интерфейса мелкие на 1920×1080; плотность деталей неодинакова. Remotion рекомендует крупный текст и щедрую безопасную область для ключевого содержания.
- Сетка на фоне соответствует визуальному языку продукта. Её стоит ослабить там, где она конкурирует с интерфейсом, но не убирать автоматически.

## Инструменты с наибольш эффектом

| Инструмент | Что даёт именно этому ролику | Когда применять |
|---|---|---|
| `@remotion/layout-utils` (`measureText`, `fitText`, `fillTextBox`) + загрузка фирменных шрифтов | Контролируемые переносы строк, размеры текста, равные заголовки и кнопки | В первую очередь; после фиксации типографической шкалы |
| Remotion Studio `Interactive` | Выделение и позиционирование важных слоёв в кадре, точная проверка координат | Для крупных UI-макетов, лейблов и движущихся элементов |
| `TransitionSeries` + фирменная motion-грамматика | Длительности и перекрытия сцен в одном месте; осмысленные переходы вместо одного fade на всё | После стабилизации макетов |
| `@remotion/paths` | Аккуратная анимация маршрута «аккаунт → репозиторий → PR → замечание → аналитика» | Для единой визуальной нити по всему ролику |
| Canvas Capture + редактируемый курсор | Чёткие фрагменты настоящего приложения с курсором как отдельным слоем | Для 2–3 коротких product-demo вставок; функция пока экспериментальная |
| `@remotion/sfx` | Тихие UI clicks, switch, whoosh и ding для действий | После сведения монтажа, точечно |

Источники: [layout-utils](https://www.remotion.dev/docs/layout-utils/fit-text), [шрифты](https://www.remotion.dev/docs/fonts), [Studio interactivity](https://www.remotion.dev/docs/studio/interactivity), [TransitionSeries](https://www.remotion.dev/docs/transitions/transitionseries), [paths](https://www.remotion.dev/docs/paths), [Canvas Capture](https://www.remotion.dev/docs/canvas-capture/how-to-use), [SFX](https://www.remotion.dev/docs/sfx), [принципы видеокомпозиции Remotion](https://github.com/remotion-dev/skills/blob/main/skills/remotion-best-practices/remotion-create/video-layout.md).

## Шаблоны Remotion и Impeccable

У Remotion есть [официальные шаблоны](https://www.remotion.dev/templates). Для этого проекта полезнее `Element Library` как пример организации собственных переиспользуемых элементов, чем готовый шаблон ролика: сюжет и фирменный интерфейс ReviewRouter всё равно нужно собирать специально. [Remotion Agent Skills](https://www.remotion.dev/docs/ai/skills) полезны для правил компоновки, студийной работы и рендера.

[Impeccable](https://github.com/pbakaus/impeccable) — набор дизайн-методов и статический детектор, не видеоредактор и не набор переходов Remotion. Для V7 разумны его `critique`, `layout`, `typeset`, `polish` и `animate`: сначала кадры как композиции, затем движение по смыслу, в конце визуальная ревизия. Его [детектор](https://impeccable.style/docs/detector/) был запущен на локальном V6: TSX — 0 находок; CSS — 3. Из них Inter действительно расходится с продуктом, декоративная сетка — осознанный брендовый мотив, боковой акцент относится к унаследованному стилю V4. Детектор не видит неровный ритм, кадрирование, состояние UI на разных кадрах и читаемость видео в движении.

## Рекомендуемый способ собрать V7

1. Зафиксировать 6–8 ключевых кадров в общей сетке: безопасное поле, две колонки, размеры заголовка, подписи, UI-макета, номер шага. В качестве основы взять настоящие токены и шрифты продукта.
2. Упростить каждый кадр до одного фокуса. Сохранить сюжет: вход → провайдер подписки → репозиторий → быстро проходящие этапы review → замечание с аватаром → метрики и графики → 9× тезис → финал.
3. Сделать связующую линию маршрута и 3 типа движения: действие пользователя (курсор/нажатие), прогресс системы (путь/счётчик/статус), переход камеры (смещение к следующему фокусу). Не применять один и тот же entrance ко всему кадру.
4. Вставить короткие записи настоящего UI там, где они усиливают доверие: выбор провайдера, включение репозитория, аналитика. Остальное оставить точной анимированной композицией. Canvas Capture можно опробовать на одном кадре до включения в финальный ролик.
5. Проверить контактные листы на ключевых кадрах, монтаж целиком на 1920×1080 и уменьшенный просмотр. Отдельно проверить линии выравнивания, перенасыщение мелким текстом и попадание интерактивных элементов в кадр на переходах.

Самый большой прирост даст не добавление эффектов, а единая сетка, реальные шрифты/элементы продукта и различимый ритм трёх типов движения. После этого blur, glow, grain и SFX можно добавлять дозированно.

Эти проекты перечислены в [каталоге ресурсов Remotion](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/resources.mdx). Сам Remotion даёт [библиотеку эффектов](https://www.remotion.dev/docs/effects): `glow`, `shine`, `noise`, `vignette`, `blur`, `lensBlur`, `lightTrail`, `magnify`, `pixelDissolve` и другие. Для нашего ролика разумный набор — приглушённый `glow` на активном маршруте, короткий `shine` на результате, лёгкий `noise`/`vignette` для глубины и `magnify` либо camera push для фокуса на реальном UI. `@remotion/motion-blur` может сгладить один быстрый пролёт камеры; его многократная выборка увеличивает стоимость рендера, поэтому не стоит применять ко всему фильму.

### Паттерны производства, которые повторяются в качественных примерах

1. **Сначала styleframes, потом движение.** В [production pipeline video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/pipeline.md) предлагают сначала 2–3 статичных ключевых кадра и визуальные токены, затем сопоставлять функцию с конкретным типом шота. Для V7 это особенно важно: V6 сразу писался как сцены в коде, без единого утверждённого масштаба UI.
2. **Один ведущий жест в каждом шоте.** Вход — клик, провайдер — выбор, репозиторий — включение, ревью — появление конкретного замечания, аналитика — рост метрик. Вторичные элементы могут двигаться тише. Это удерживает внимание на продукте.
3. **Пауза после движения.** Рецепты сообщества специально оставляют время на прочтение результата. Если шот всё время «живёт», пользователь не успевает увидеть состояние интерфейса.
4. **Монтаж по акцентам музыки, но без постоянных ударов.** Сильные звуковые и визуальные акценты лучше оставить для 2–3 моментов: включение review, найденное замечание, цифра результата. Остальные действия звучат как тихие UI-сигналы. В Remotion есть готовые [SFX](https://www.remotion.dev/docs/sfx).
5. **Реальный UI с измеренными координатами.** Примерный workflow собирает 2× скриншоты отдельных элементов и их bounding boxes, чтобы камера точно попадала в цель; [Canvas Capture](https://www.remotion.dev/docs/canvas-capture/how-to-use) предлагает иной путь с записью и отдельным курсором. Для наших сцен лучше короткие реальные фрагменты поверх анимированной композиции, чем воссоздавать весь интерфейс на глаз.
6. **Проверка не только стоп-кадрами.** Сравнить начало, кульминацию и конец каждого шота, затем смотреть непрерывный экспорт с музыкой. Официальный Remotion требует детерминированной анимации от `useCurrentFrame()`; CSS-анимации и случайное состояние приводят к [мерцанию](https://www.remotion.dev/docs/flickering).

### Конкретная режиссура следующего фрагмента

Для проверки направления до переработки всех 27 секунд сделать 6–8-секундный фрагмент **«провайдер → репозиторий → первое замечание»**:

- Провайдеры собираются в ровную сетку, курсор выбирает один, остальные приглушаются. Подходящий референс — [`chip-grid-single-select-blackout`](https://vincentwei1021.github.io/video-shotcraft/).
- Активная линия выходит из выбранного провайдера и становится разделителем на экране репозитория. Референс — [`line-carry-transition`](https://vincentwei1021.github.io/video-shotcraft/).
- После включения review этапы проходят короткой последовательностью; камера следует за одним активным состоянием, затем резко останавливается на замечании с аватаром. Референс — [`scanline-annotate-focus`](https://vincentwei1021.github.io/video-shotcraft/).

Такой пробный фрагмент покажет, работает ли новая motion-грамматика, читаемость интерфейса и звуковой ритм, до затрат на весь V7. V6 останется точкой сравнения.

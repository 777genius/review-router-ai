# Публичный каталог моделей OpenAI, Anthropic и OpenRouter

Статус: план реализации, после отдельного прохода `plan-improve` и `q`.
База: `origin/main` `bb277462bed5135a838b20d07eeae69034562bd8`, 2026-10-21.
Связанный, независимо реализуемый план: [учёт расхода](57-provider-usage-implementation-plan.md).

## Результат и границы

В выборе модели показывать актуальные публичные модели OpenAI, Anthropic и
OpenRouter без авторизации для получения списка. Использовать существующий
`review-providers`, его `ProviderModelCatalogPort` и серверную загрузку страницы.
Публичный справочник не является подтверждением доступа по OAuth, подписке,
ключу или Gateway-профилю. Для загрузки справочника не нужны служебный аккаунт,
пользовательский токен и запуск coding agent.

В этой задаче нет новых способов аутентификации, поддержки Anthropic Gateway,
изменений протокола inference и снятия ограничений аккаунтов. Каталог должен
работать с существующими способами подключения. MiMo сохраняет текущий список.

## Что уже есть и какие источники использовать

| Провайдер в UI / существующий `ProviderKind` | Публичный источник                                        | Правило идентификатора                                                                      |
| -------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| OpenAI / `codex`                             | `GET https://models.dev/api.json`, только `openai.models` | Использовать `model.id` выбранного провайдера, без добавления `openai/`                     |
| Anthropic / `claude`                         | Тот же ответ, только `anthropic.models`                   | Нативный `model.id`; сохранить поддерживаемые CLI-алиасы `sonnet`, `opus`, `haiku` отдельно |
| OpenRouter / `openrouter`                    | `GET https://openrouter.ai/api/v1/models`                 | Сохранить полный `data[].id`, включая vendor prefix и `:free`                               |

`models.dev` - открытый сторонний справочник, а не официальный API доступности
OpenAI/Anthropic. Не использовать OpenRouter ID как нативный ID через удаление
префикса. `canonical_model_id` пригоден для отображения/связей, но не заменяет ID
запроса. Существующие `ProviderKind` и сохранённый Gateway wire format не менять.

Проверено 2026-10-21: анонимный GET OpenRouter вернул 200 и 468 записей;
`models.dev/api.json` с обычным идентифицирующим User-Agent вернул 200,
6 074 349 байт, 51 модель OpenAI и 17 Anthropic. Первый запрос Python urllib
вернул 403. Это аргумент за кэш и обработку отказа источника, не обещание SLA.
В текущем ответе есть image-модели, поэтому фильтр назначения обязателен.

Точки изменения:

- `packages/features/review-providers/src/application/ports/provider-model-catalog-port.ts`
  и `application/use-cases/list-review-model-options.ts`: сейчас динамически
  запрашивается только OpenRouter, остальные списки статические.
- `infrastructure/openrouter/openrouter-model-catalog.ts`: уже есть TTL 30 минут,
  cooldown 5 минут, timeout 4 секунды и fallback. Расширить этот механизм без
  второго независимого кэша с теми же правилами.
- `apps/web/src/server/openrouter-model-catalog.ts` и
  `apps/web/app/dashboard/dashboard-workspace-page.tsx`: серверная композиция
  и первый рендер. Сохранить совместимость публичных вспомогательных функций,

- `apps/web/app/dashboard/repository-policy-editor.tsx` и
  `apps/web/src/server/gateway-model-account-options.ts`: применение каталога
  к выбранному провайдеру/подключению. Серверный профиль остаётся authority.

## Контракт и направление зависимостей

`review-providers` владеет нормализованным снимком каталога: провайдер, список
моделей, источник, `fetchedAt`, `lastAttemptAt`, состояние
`fresh | stale | fallback | unavailable`. У модели есть нативный ID, название,
контекст, известные возможности и необязательные публичные цены с единицами.
Неизвестное значение представлять `null`/`unknown`, не `false` и не нулём.

Изменить результат существующего порта на такой снимок и обновить его реальные
потребители одним связным изменением. Не создавать отдельный универсальный
«адаптер провайдера» с обязательными usage/limits методами. HTTP-парсеры и кэш
остаются внешними адаптерами; домен не импортирует Next.js, fetch DTO, SDK,
Get Modular или Engineering Foundation.

Нормализацию назначения, дедупликацию по `(providerKind, nativeModelId)` и
сопоставление с подключением держать в `review-providers`. React-компонент
только отображает готовые состояния. Отдельного сервиса каталога и БД не нужно.
Публичные цены могут позднее читаться `provider-usage` через его потребительский
порт; обратной зависимости каталога от учёта расхода нет.

Get Modular использовать в одной серверной composition surface для построения
снимков через типизированные зависимости: HTTP, часы, источник моделей и политика
кэша. Engineering Foundation использовать только в dev tooling для границ
этого seam и публичных экспортов. Версии, API и минимальная квалификация общие
с [шагом 0 плана учёта](57-provider-usage-implementation-plan.md#шаг-0-совместимые-библиотеки-и-границы).
Каталог может идти первым и выполнить этот шаг самостоятельно; повторять
установку или создавать второй профиль инструментов не нужно.

## Нормализация и совместимость выбора

1. Читать только разрешённые provider keys. Валидировать ID по существующему
   безопасному формату имени модели, ограничить длины строк и числа;
   HTML/description из внешнего ответа не интерпретировать как разметку.
2. Для review подходят модели с текстовым входом и текстовым выходом.
   Image/audio/embedding/rerank-only модели исключить из выбираемых вариантов.
   В models.dev читать `modalities.input/output` и `tool_call`; в OpenRouter -
   `architecture.input_modalities/output_modalities` и наличие `tools` в
   `supported_parameters`. Отсутствующее поле означает `unknown`, явное false
   или несовместимый modality - неподдерживаемую возможность. Для agentic mode
   требуется явно известная поддержка tool calling. Существующие
   поддерживаемые алиасы/defaults сохранить как локальную политику совместимости.
   Локальная проверенная совместимость runtime/алиасов имеет приоритет перед
   внешними метаданными. Tool calling в каталоге не доказывает поддержку
   Responses/CLI transport; применять отдельные существующие ограничения runtime.
   Не выводить reasoning/fast-mode возможности из имени модели. Если metadata
   недостаточно для безопасного выбора, вариант виден с причиной недоступности.
3. Для GitHub Secrets/OAuth показывать публичные подходящие варианты и разрешать
   выбирать нативный ID, если существующий runtime принимает такой ID.
   Доступ по аккаунту: `not_checked`. До сохранения проверять известные
   ограничения конкретного runner/режима; неизвестная подписка сама по себе
   не блокирует выбор. Ошибка реального запуска явно объясняет отказ модели.
4. Для Gateway список разрешённых ID берётся из авторизованного профиля.
   Публичный каталог добавляет названия/метаданные, но не расширяет allowlist.
   Профильный ID, которого нет в публичном источнике, остаётся выбираемым при
   существующей серверной проверке. Публичный ID вне профиля отображается
   недоступным с причиной. OpenRouter Gateway использует профильные ID и mapping,
   а не автоматически все глобальные OpenRouter модели.
5. Новые публичные ID не получают автоматически `max/ultra`, fast mode или иной
   неподтверждённый capability. Известные несовместимые настройки требуют
   явного исправления перед сохранением; не менять effort/model молча.
6. Сохранённая модель, исчезнувшая из источника, остаётся видимой как текущая
   с пометкой «нет в текущем каталоге». Обновление справочника не переписывает
   конфигурацию и не переключает на первый вариант. Для Gateway действующая
   серверная проверка профиля сохраняется, включая отказ устаревшему binding.
7. При переключении провайдера/подключения сохранять действующие правила очистки
   несовместимого model/binding и исправления PR #634: выбор не должен путаться
   между строками после удаления provider row.

## Сеть, кэш и ошибки

- Два фиксированных HTTPS URL; браузер не передаёт upstream URL или заголовки.
  Только Accept и идентифицирующий User-Agent, без Authorization/cookies.
  Не следовать редиректам за пределы разрешённого источника.
- Два запроса выполнять параллельно. Models.dev читать один раз для двух
  провайдеров. Timeout 4 секунды на источник, декодированный ответ максимум
  16 MiB; Content-Length сам по себе не достаточен. Не грузить весь каталог
  сотен провайдеров в browser payload.
- Один in-flight refresh на источник и один снимок на серверный процесс;
  отмена одного потребителя не отменяет общий refresh других. Результат
  отменённой загрузки не применяется к другому выбору/странице.
- Для models.dev хранить отдельные successful snapshot/fetchedAt/error для
  секций OpenAI и Anthropic при одном общем HTTP refresh. HTTP failure включает
  общий cooldown; validation failure - cooldown/возраст только повреждённой
  секции. Успешная соседняя секция не очищает её ошибку. Пока хотя бы один
  запрошенный provider нуждается в допустимом refresh, общий source fetch может
  обновить обе секции с независимой публикацией результата.
- TTL 30 минут, cooldown после ошибки 5 минут. Возраст последнего успешного
  снимка до 24 часов допускает `stale`; после этого использовать локальный
  fallback и отдельное описание отказа. До первой успешной загрузки тоже fallback.
  Перезапуск процесса допустимо теряет кэш. Redis/cron не добавлять.
- Публиковать снимок атомарно для каждой provider section после валидации. Повреждение provider section
  OpenAI не стирает валидный Anthropic snapshot. Невалидные отдельные строки
  пропускать с безопасным счётчиком; конфликтующие одинаковые ID и отсутствие
  всех валидных записей считать ошибкой соответствующего provider section.
- OpenRouter failure не должен блокировать OpenAI/Anthropic и наоборот.
  Пустой/сломанный ответ не заменяет последний хороший снимок пустым списком.
  Успешное исчезновение части моделей обновляет каталог, сохраняя отображение
  уже выбранных моделей по правилу выше.

## UI и порядок реализации

1. Выполнить общий шаг совместимости библиотек. Затем добавить models.dev adapter
   и единый snapshot/result contract, расширить существующий OpenRouter adapter.
2. Подключить оба адаптера через Get Modular в серверном composition root,
   обновить `list-review-model-options` и first-paint loader. Локальные алиасы и
   fallback объединять детерминированно, без дублей и скрытых замен ID.
3. В существующем поле Model добавить источник/актуальность и подпись
   «Доступ по аккаунту не проверен» для публичного выбора. Сохранить существующий
   Test connection для Gateway и его реальный loader/progress. Не запускать
   inference автоматически ради просмотра каталога.
4. Для ручного обновления/повторного чтения использовать React Query с ключом
   `['provider-model-catalog', providerKind]`, функцией в API adapter и
   `staleTime` 30 минут для fresh и 0 для stale/fallback/unavailable.
   Начальные данные передаёт loader с `initialDataUpdatedAt` по успешному
   `fetchedAt`, а не времени рендера; при его отсутствии использовать 0.
   Автоматический refresh соблюдает TTL/cooldown. Ручной refresh запрашивает
   revalidation мимо TTL, но соблюдает серверный cooldown и single-flight;
   сервер допускает не чаще одного ручного refresh на source в минуту
   на процесс, независимо от пользователя. Ответ явно сообщает,
   обновлён ли источник или действует cooldown, не создавая видимость нового fetch.
   Публичный кэш не содержит account/binding; пересечение с профилем
   авторизуется отдельно и не кэшируется глобально. Не копировать query data
   в независимый React state. UI обновления доступен по всем трём провайдерам.
5. Добавить Foundation checks к существующему architecture gate для принятого
   seam. Не переносить весь монорепозиторий на другую модульную систему.

Два связных PR: адаптеры/контракт/композиция, затем UI/интеграция. Если общий
diff невелик, один PR допустим. Подготовка библиотек отдельным prerequisite,
если требует toolchain changes. Ориентир: 650-1 100 production LOC и
300-550 test LOC, плюс общий prerequisite из плана учёта; lock/generated отдельно.

## Проверка и приёмка

Расширить существующие `provider-model-catalog.test.ts`, OpenRouter adapter tests,
`apps/web/src/server/openrouter-model-catalog.test.ts` и provider-policy UI tests.
Новые проверки нужны для: двух разных provider namespaces в одном ответе,
единиц цены (models.dev за 1M, OpenRouter за token), не-text моделей,
malformed/oversized ответа, stale/fallback, параллельного refresh и отмены одного
ожидателя. Часы/fetch должны инъектироваться одинаково в production и тестах;
текущий обход cache при custom fetch не использовать для тестов самого cache.

Браузерный сценарий на существующем disposable harness: OpenAI/Anthropic/
OpenRouter публичный выбор, смена подключения/удаление строки, обновление
списка без изменения текущего model, Gateway allowlist и отсутствие автозапуска.
Не делать E2E зависимым от конкретного текущего количества внешних моделей.
Один анонимный HTTP smoke при квалификации подтверждает доступность источников;
обычный CI использует сохранённые минимальные fixtures.

При реализации: focused Vitest по изменённым каталогам/UI, typecheck web и
review-providers, `pnpm architecture:check`, существующие lint/build и обязательный
CI актуального PR. Проверки Get Modular/Foundation выполняются на реальной сборке
и включают отрицательный import из domain в HTTP/Prisma/другую feature internals.
Отдельно доказать, что никакие внешние capability flags не включают неподдержанный
runtime mode, а Gateway account-derived entries не оказываются в публичном query DTO.

Готово, когда все три списка грузятся без токенов, их источник и актуальность
видны, сохранённые конфигурации не меняются при refresh, а public catalog не
обходит серверные ограничения. План не обещает OAuth entitlements из публичного
источника. Доставка реализации следует существующему release runbook; в рамках
подготовки этого плана ничего не выкатывается.

## Уточнения после `plan-improve`

Устранены исходные неоднозначности: публичный источник для OpenAI/Anthropic
назван прямо; ID трёх транспортов не смешиваются; account access отделён от
catalog presence; Gateway сохраняет профильный allowlist; определены partial
failure, возраст stale, сохранение исчезнувшего выбора и общий in-flight refresh.
Совместимость библиотек проверяется до их подключения, без скрытой миграции TS.

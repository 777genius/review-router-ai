# Finding revalidation: bounded implementation notes

The accepted plan requires the disposable live canary to capture an aggregate Gateway grant of **R=9**, without changing the shared provider profile. Fresh production readiness inspection found all approved profiles configured at R=640 and no existing trusted per-scope lowering adapter. Observed request usage below nine would not prove the required grant.

The existing server admission policy now accepts the optional operator environment variable `REVIEW_ROUTER_GATEWAY_REQUEST_CAPS_JSON`: a strict JSON array of at most 128 exact rules. Every rule requires `workspaceId`, `repositoryConnectionId`, `scmRepositoryIdentityId`, `pullRequestNumber`, `profileRef`, `bindingId`, and positive integer `maxRequests`. Duplicate selectors, unknown fields, wildcards, and partial selectors are rejected. The configuration contains no credentials.

All six selectors must match the verified SCM identity and saved Gateway connection. Admission captures `min(existingApprovedRequests, maxRequests)` in the immutable runtime snapshot. The existing native Prepare adapter consumes those captured limits unchanged. A rule cannot select a model/account, raise an allowance, partition discovery/companion budgets, or introduce a caller-controlled request parameter.

Normal restore keeps the original captured grant: removing or raising a rule never enlarges an admitted R=9 run. Applying a lower rule makes a previously captured larger grant fail the existing `isLive` guard in that exact scope. Therefore the disposable canary scope must be verified idle before installing its rule, and use fresh run identity. Unrelated scopes and shared R=640 profiles remain unchanged. Removing the rule permits future ordinary admissions at the original approved profile limit.

This is an adapter for the accepted canary's finite-grant prerequisite, not a new quota service, ledger, public API, UI, or test-only invocation path. Source changes alone do not install a rule or perform production/model effects.

## Initial history bootstrap

The installed legacy handlers do not track all entered effect promises. Retiring their deployment cannot prove that every historical target has an exact terminal outcome. The initial `retired_legacy_writers_quarantine.v1` bootstrap therefore records real writer-retirement proof and an activation cut in the nullable connection field `lifecycleResolutionBootstrapJson`, without inventing pending operation, head, body, or effect identities.

Under this bootstrap, every target whose parent was created at or before the cut remains manual because an untracked old mutation is possible, including a thread that becomes visible only later. Those historical targets are not automatically resolved. The live canary's four historical fixture threads therefore cannot demonstrate automatic closure through this bootstrap; positive verification must use trusted threads created after the cut. Newer parents are eligible under the ordinary exact-head, source, discovery, and publication guards. Existing qualified activation semantics remain unchanged when the bootstrap field is null.

The quarantine qualification port must verify the actual complete set of old managed legacy resolution executors across all repository connections, because the old global thread-node lookup did not bind a thread to its authenticated repository/PR. Every old executor must be retired and nonrestartable, and old ingress must reach none of them. A per-connection census, idle counter, elapsed wait, or renamed handler-settlement receipt is insufficient. The proof binds the executor-set hash, retirement/ingress observations, and source-owned proof hash; the connection stores only the small proof binding and database activation cut. It does not claim that old effect promises reached terminal outcomes.

The corrected legacy writer verifies the native thread's stable GitHub repository ID and PR number before mutation. Its qualification source version is `rr_legacy_resolution_writer.v2_repository_pr_membership`; `legacyResolutionWriterSourceIdentity()` hashes actual loaded module-file bytes with that version instead of publishing a fabricated digest. New canonical capability issuance checks the quarantine barrier under the connection row lock using the captured selected target's real parent creation timestamp; absent metadata refuses issuance. Existing positive and pending operations retain their actual identities and reconciliation semantics. No production writer retirement, activation, GitHub mutation, or model invocation is performed by these source changes.

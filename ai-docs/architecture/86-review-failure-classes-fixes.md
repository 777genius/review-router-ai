## Класс 1 подробнее

- Точные цитаты нигде не хранятся: в логе только счётчики, в evidence только нормализованные находки. Поэтому по каждому прогону форма ошибки не доказана.
- Доказано по коду: локатор OCR (`internal/diff/resolver.go`) снимает `+`/`-` и обрезает пробелы в каждой строке (`normalizeLine`), пропускает пустые строки (`splitAndNormalize`) и ищет в удалённых строках. Схема инструмента просит "consistent style with diff code". `verifyOcrSpan` ищет точную подстроку. OCR ставит комментарий, а RR называет его необоснованным.
- Примеры: social-monitor 44417115414 (в тексте находки настоящий TAB там, где в исходнике `\t`, то есть модель потеряла JSON-экранирование), canary PR 143 (находка про `items.slice(...)`: файл из 15 строк целиком в diff, эта строка встречается один раз). В проверенных случаях находка реальная, значит это ложный красный.
- Цена: на зелёном прогоне сводка больше не объясняет, почему у находки нет inline-якоря, а изменения жизненного цикла применяются. Если цитата была выдумана моделью, это не видно. Доля таких случаев неизвестна.
- Не делаем пока: сравнение цитат как в OCR. Вернёт inline-якоря, но без записанных цитат нельзя доказать, какие формы реально встречаются. Дешёвый следующий шаг: счётчики форм несовпадения в acceptance-логе без содержимого.

## Отложенные шаги (порядок native -> Gateway -> SaaS -> Action)

1. native, ~2 ч: статус NVIDIA перед голым 502 в Chat-мосте через уже разрешённое событие `gateway_native_response_failure` (phase `http_status`). Свою строку stderr Gateway отбросит: он пропускает только события из списка. Поведение не меняется.
2. SaaS relay, ~0.5 дня, затрагивает путь авторизации: в catch `scopedResponse` отдавать код из `safeFailure` (код Gateway или отказ авторизации). Статус остаётся 502, эффект берётся из фактического расчёта (`failureEffect`). Runtime добавляет эти коды в список диагностики (следующий Action).
3. SaaS relay, класс 4, затрагивает custody: сессии без удерживаемой capability relay уже освобождает. Застревают только сессии с удерживаемым bearer, а правила "never discard a retained bearer" и "never free unknown custody" (`2026-11-02-gateway-terminal-run-cleanup.md`) это запрещают. Любое освобождение таких сессий меняет custody и требует решения владельца. Сначала лог причины, по которой close вернул unknown. Поднимать `maxSessions` бесполезно.
4. Action (runtime), класс 2, вытеснение: считать отмену из-за новой ревизии отменой, а не исчерпанием провайдера. Это тот же хвост, что runtime #395 оставил для `synchronize`.
5. Action (runtime) и эндпоинт SaaS для SCM-токена, класс 2, сбой проверки ревизии. Plan 71 (раздел 5) закрыл этот код как разовый сбой без правок. Он повторился 20.11 в 03:12, это до замены образа в 03:30, так что выкатка не причина. Причина снова не установлена. Вариант: при кратком сбое дать текущим потокам доиграть и обрывать только при подтверждённой смене ревизии. Это меняет поведение авторизации, нужно решение владельца.

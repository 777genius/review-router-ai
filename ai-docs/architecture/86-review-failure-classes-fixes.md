## Класс 1 подробнее

- Точные цитаты нигде не хранятся: в логе только счётчики, в evidence только нормализованные находки. Поэтому по каждому прогону форма ошибки не доказана.
- Доказано по коду: локатор OCR (`internal/diff/resolver.go`, `normalizeLine`) снимает `+`/`-`, обрезает пробелы в каждой строке, пропускает пустые строки и ищет в удалённых строках. Схема инструмента просит "consistent style with diff code". `verifyOcrSpan` ищет точную подстроку. OCR ставит комментарий, а RR называет его необоснованным.
- Примеры: social-monitor 44417115414 (в тексте находки настоящий TAB там, где в исходнике `\t`, то есть модель потеряла JSON-экранирование), canary PR 143 (находка про `items.slice(...)` в файле из 15 уникальных строк). В проверенных случаях находка реальная, значит это ложный красный.
- Не делаем пока: сравнение цитат как в OCR. Вернёт inline-якоря, но без записанных цитат нельзя доказать, какие формы реально встречаются.

## Отложенные шаги (порядок native -> Gateway -> SaaS -> Action)

1. native, ~2 ч: строка диагностики со статусом NVIDIA перед 502 в Chat-мосте. Поведение не меняется. Сначала проверить, что stderr движка доходит до журнала Gateway.
2. SaaS relay, ~0.5 дня, затрагивает путь авторизации: в catch `scopedResponse` отдавать код из `safeFailure` (код Gateway или отказ авторизации), а эффект и статус оставлять от фактического расчёта (`failureEffect`). Runtime добавляет эти коды в список диагностики (следующий Action).
3. SaaS relay, класс 4, затрагивает custody capability: сначала лог состояния удержанных сессий при `relay_saturated`, потом освобождать сессию, чья авторизация отозвана или истекла, когда очистку уже держит дедлайн Gateway. Поднимать `maxSessions` бесполезно.
4. Класс 2, вытеснение: считать отмену из-за новой ревизии отменой, а не исчерпанием провайдера. Это тот же хвост, что runtime #395 оставил для `synchronize`.
5. Класс 2, сбой проверки ревизии: решение владельца. Вариант: при кратком сбое чтения GitHub дать текущим потокам доиграть и обрывать только при подтверждённой смене ревизии. Это меняет поведение авторизации.

## Что нужно от владельца

- Не ставить `:free` модель единственным ревьюером.

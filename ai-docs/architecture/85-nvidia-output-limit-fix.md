# Ревью NVIDIA теряется из-за лимита вывода (2026-11-20)

Статус: исправление runtime в PR (777genius/review-router#401). Релиз Action и деплой не входят.
Источник: read-only выборки из БД RR и kernel Gateway на prod, логи прогонов `ReviewRouter` за 2026-11-17..19, код runtime (Action 241), Gateway и native.

## Что видно на prod

- Слот OCR один на весь PR (`requiredTotal` = 1, `attemptBudget` = 1). Файлы на группы делит сам OCR. Планировщик юнитов тут не виноват.
- Kernel Gateway, профиль `nvidia-build-chat-apikey-v1`, 5 дней: 17 ходов закончились ровно на 32768 токенах вывода, это около 1 из 200 ходов. Чаще всего это убежавшее рассуждение (reasoning = 32768) или петля повторов в тексте (вывод 32768, reasoning меньше 100).
- Потолок 32768 задаёт `limits.maxOutputTokens` профиля диспетчеризации RR, и он же стоит в `max_tokens` исполнения Gateway. OCR `--max-tokens` = 87381 из #397 ограничивает историю, а не вывод, и к этой проблеме не относится.
- За 3 дня 136 исчерпанных слотов. По логам 16 из них (NVIDIA) заканчиваются одинаково: `gateway: unrecognized/completed` и уведомление про лимит вывода. Примеры: review-router-ai #914, прогон 44607155032, 131 файл, потеря через 26 мин. social-monitor #665, прогоны 44599368139 и 44610893841, 672 файла, потеря через 26 и 4 мин.

## Где расхождение

Native и Gateway работают верно: native переводит `finish_reason=length` в Responses `status: incomplete` + `max_output_tokens`, Gateway закрывает запрос как `completed`, runtime распознаёт это как `output_truncated`/`completed` (Action 236).
Ломается runtime дальше:

1. Транспорт после такого ответа ставит `inferenceDenied`, и все следующие запросы OCR отклоняются локально (в 44610893841 их 1066 за секунду).
2. Приёмка пропускает только эффект `none`, поэтому `completed` превращается в `gateway_effect_unknown`.
3. Попытка одна, поэтому теряется весь PR (0/N файлов).

`unrecognized` в логе означает только, что кода `output_truncated` нет в списке диагностики.

## Выкатка

- Нужен только релиз Action 242. Native, Gateway, RR API, схема и миграции не меняются. Порядок native -> Gateway -> RR -> Action не затронут.
- После релиза такие ревью заканчиваются как partial с уже существующим уведомлением о лимите вывода. Группа с обрывом попадает в неполное покрытие.
- Риск: до 4 оплаченных убежавших ходов (около 32k токенов каждый) на потребителя, 4-й ставит прежний забор. Тогда ревью теряется как раньше, но локальная причина будет `actual_model_missing`, а не `gateway_effect_unknown`. Эти токены видны в usage Gateway, но не в строке usage OCR. Заменено планом [87](87-nvidia-large-pr-stability.md): 4-й ход по-прежнему ставит забор, но готовые группы остаются частичным ревью.
- Изменение касается всех потребителей транспорта (Codex, lifecycle verification, описание PR). Codex повторяет упавший поток с новыми байтами и может оплатить до 4 обрывов вместо одного.
- OCR v1.13.1 (`reviewResultError`) выходит с ненулевым кодом только при сбое уровня run или когда упали все группы. В 44610893841 код 1 был из-за того, что забор уронил все группы. Если лимит поймает шаг уровня run, а не группы, ревью по-прежнему потеряется.

## Не входит (другие классы того же среза, 3 дня)

- 17 слотов: 502 от relay с кодом, которого нет в списке runtime, эффект `effect_unknown`.
- 23: обрыв потока `transport/effect_unknown`.
- 13: `relay_saturated`/`not_dispatched` примерно через 2.5 мин.
- 16: квота OpenRouter `:free`.

Каждому нужен свой разбор. Этот фикс закрывает примерно 15% исчерпанных слотов, а не все 54%.

## Quiet window: rule used

Strict: `busy=0` in every 15 s sample for 120 s consecutive, counting live
executions (active invocation lease, lease renewal in the last 10 minutes or
created in the last 10 minutes), any `in_progress` ReviewRouter Actions run of
a repository with a recent execution, outbox events in `processing` or with an
unexpired claim, active publication claim terms, publication attempts
`publishing` or `reconciling`, publication operations in flight with an
unexpired reconcile window, active operation attempts with an unexpired effect
window, claimed or fresh completion processes, claimed progress publications,
investigation turns leased in the last 15 minutes and active investigation
leases. Every database session uses `SET LOCAL TIME ZONE 'UTC'`, because the
columns are `timestamp without time zone` in UTC and the server zone is not
UTC.

## Why two fleet runs and not one

The image swap and the FILE 70 cohort could not be one operation. The
fleet-overlay tool keeps `HostConfig` (the binds) identical, so it cannot move
the producer registry mount, and the reviewed FILE operator asserts that the
installed revision equals its constant ("never changes the image") and refuses
the release identity keys. Folding them together would have needed a new,
unreviewed operator. So they ran back to back, image first: the intermediate
state (new image, FILE 69, Action refs 241) is a normal production state, and
the rollback order becomes cohort first, then image. The point to go back to
before this rollout is the single set `*-before-ovl-20261120033036871`;
`*-before-file70-retained` is only the intermediate state.

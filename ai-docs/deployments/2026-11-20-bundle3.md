## Compatibility of the native TTL change

- Native now sets `expiresAt` = `fetchedAt` + 5 minutes on every account model
  snapshot (catalogue, Codex, OpenRouter) and keeps cached Codex and
  OpenRouter snapshots until that `expiresAt`.
- Gateway 115 (`models-port.ts`) passes a snapshot through and turns it into
  `unknown` only when `fetchedAt` is in the future or `expiresAt` has passed;
  its contract (`validSnapshotPeriod`) only needs `fetchedAt < expiresAt`. No
  upper bound on the lifetime, so no Gateway change.
- ReviewRouter, old (`d2f42908`) and new images alike, checks only
  `fetchedAt <= now < expiresAt` (`review-run-gateway-model-settings.ts`,
  `action-conversation-policy.ts`, `gateway-model-account-options.ts`,
  `dashboard-provider-setup-readiness.ts`); none of these files changed
  since `d2f42908`. The Web refresh schedule
  (`account-model-catalog-freshness.ts`, #932) reads the list again
  `min(5 min, lifetime / 4)` before `expiresAt`: with 5 minutes about 75 s
  before expiry instead of every 45 s.
- So the intermediate state native-new + ReviewRouter-old is a normal state,
  and a native rollback under the new image is safe too.

## Quiet window: rule used

Strict, as in the [second bundled rollout](2026-11-20-bundle2-action-242.md#quiet-window-rule-used):
`busy=0` in 8 consecutive 15 s samples, counting live executions, any
`in_progress` ReviewRouter Actions run of a repository with a recent
execution, outbox claims, publication claims and attempts, completion
processes, progress publications and investigation leases; not between
xx:07 and xx:10 (hourly maintenance); every database session with
`SET LOCAL TIME ZONE 'UTC'`. The native step also needs the Gateway kernel
idle (occupied, inflight and cleanup 0), checked by the poll and again by
its operator.

One change, confirmed by the orchestrator before the apply: a publication
attempt in `publishing` or `reconciling` counts only if it has an active,
unexpired claim term or was created in the last 15 minutes (active claim
terms always count). Reason: the attempt of review-router-ai PR 944 (a docs
PR, execution `completed`) stayed `publishing` from 04:27 to about 06:35 and
was re-claimed every five minutes with 60-second claims, so the old
predicate could never reach `busy=0`. It cleared by itself before the
windows; every other signal is unchanged.

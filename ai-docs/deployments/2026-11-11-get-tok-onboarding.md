## UX findings and follow-up

- **Critical — duplicate identity and misleading waiting status:** a submitted new Codex account remained in a waiting state while Gateway had already classified the new account as quarantined with `principal_claim_scope_mismatch`. PR #853 corrects the unknown-status projection only; it neither removes the principal conflict nor proves fresh OAuth. Preserve the identity/custody guard and do not retry an unknown create or delete an existing account.
- **Medium — repository sync visibility:** immediately after GitHub App installation the workspace showed a connected source but no repositories and suggested reconnecting. The repository appeared after ordinary reload; add clear sync progress, an appropriate refresh path and an accurate empty/error state.
- **Medium — model refresh feedback:** initial catalog loading failed while duplicate refresh controls showed conflicting failure and up-to-date messages; one manual refresh recovered. Consolidate the controls and reflect the actual request state.
- **Medium — access dialog navigation:** adding the shared connection opened overlapping Add account and Access dialogs; `Choose in Models` led first to Review settings rather than directly to Providers. Correct the dialog flow and destination.
- **Medium — Usage measurement explanation:** all token observations were eventually reported, while the global footer still said some usage was unknown or partial because other dimensions such as cost remained unavailable. Explain which measurement is missing instead of suggesting token loss; this is follow-up work, not part of the current release.
- **Low — duplicated finding text:** the inline review repeated the explanation as both bold title and body. Keep the title concise and the explanatory body distinct.

The GitHub Confirm Access step was an external authentication requirement, not a ReviewRouter defect. The setup action correctly reported a missing-provider prerequisite when attempted; no silent-guard defect is claimed.

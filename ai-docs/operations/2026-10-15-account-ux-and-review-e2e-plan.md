## 3. Accounts UX: реализованный source scope

Ниже отметки относятся к source implementation и независимому review final r2; они не обозначают production/browser acceptance. Фактические проверки и доставка фиксируются отдельно в §5–6.

- [x] Одно понятное личное заглавие **«Мои аккаунты»** с действиями подключения, управления и предоставления доступа; убрать дублирующиеся «connections/accounts» блоки одного owned source. Организационный раздел отдельно: **«Аккаунты, доступные в <организации>»**.
- [x] Для доступного пользователю личного source показывать связь: **«Ваш личный аккаунт · доступен в этой организации»**; для org-owned: **«Принадлежит организации»**. Объяснить, что используется один аккаунт с общей авторизацией и capacity. Не раскрывать имена недоступных организаций/чужого владельца.
- [x] Развести действия: **«Предоставить доступ организации»**, **«Убрать доступ этой организации»**, **«Отключить аккаунт везде…»**. Локальный detach не удаляет credential/source и не отключает другие организации. Permanent retirement явно перечисляет последствия для всех организаций и личного пространства; Cancel в фокусе, открытие/отмена без reservation или запроса.
- [x] Каждый batch-result связывать с авторизованными account + organization, а не только UUID: **«Доступ предоставлен»**, **«Подтверждаем удаление доступа»**, **«Не удалось подтвердить результат»**. Показывать независимые результаты каждой пары; одно неизвестное состояние не становится общим «успехом».
- [x] Pending/unknown не создаёт новый intent и не вызывает автоматический retry. Owner-операции используют read-only operation status. Для recipient detach кнопка Check confirmation вручную повторяет прежний idempotent request с теми же bindingId и expectedBindingRevision и сверяет тот же fence; это не отдельный read-only API. Уже revoked binding не проходит retire повторно, новый lifetime не подставляется. Не стирать fence/history и не маскировать неопределённость словом «Удалено»; потеря роли/сессии сохраняет серверные deny-границы.
- [x] Отозванный saved binding остаётся недоступным. После reattach пользователь явно выбирает новый доступный binding и сохраняет; подсказка **«Выберите доступный аккаунт ещё раз и сохраните»** плюс настоящая ссылка Accounts. Никакого silent rebind/default switch.
- [x] Совместить с P2 другого чата: при Providers=Inherit override controls не редактируются и не блокируют save неиспользуемым draft; после успешного save форма показывает принятый revision/effective account. Ошибка сохраняет unsaved draft. Полное удаление overrides имеет отдельное имя/confirmation и не подменяет providers inherit.

Не обещать suspend/resume или OAuth reauth, если текущая capability не поддержана. Backend lifecycle и immutable source/binding identity сохраняются.

Root этого чата — единственный production writer общей партии; этот план не создаёт вторую установку/переключение.
3. Common renderer, two MiMo review cases и browser UX checks имеют конечные receipts с exact source/head/run/account scope, ожидаемым result и closure. Для account UX требуется **реализованный и проверенный** §3, не только retirement confirmation или этот документ.
4. Отдельно перепроверить актуальный остаток Norm53/Plan56: другой provider E, protected OAuth F, retirement G, native exact-source CI и другие ранее открытые qualification gates получают статус только из собственных актуальных receipts. Этот MiMo E2E не доказывает все provider profiles, memory, multi-provider matrix или все H lifecycle cases. Не перезапускать исторически принятые paid runs только ради новой сводки; не объявлять нечитанный gate пройденным/отсутствующим.

Итоговый статус разделяет: source merged, artifact published/installed, browser UX accepted, clean review accepted, seeded review accepted, controlled lifecycle accepted и оставшиеся внешние gates. До выполнения этих пунктов результат обозначается частичным с конкретным следующим шагом.

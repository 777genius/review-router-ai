# Reviewed UAP MCP presets

The dashboard uses a checked-in, reviewed MCP catalog of the [Universal Agent Plugins registry](https://github.com/777genius/universal-agent-plugins-registry/tree/803f82a0ea89c634a5a22a070d19473ee41d18a9). It does not install packages, follow a mutable branch, execute registry commands, or fetch registry content during a request.

`apps/web/src/server/mcp-catalog-data/uap-reviewed.json` is derived from immutable registry commit `803f82a0ea89c634a5a22a070d19473ee41d18a9`, `registry/directory.json`. Each row retains the product/default distribution, exact active release, package source, original release sequence and tree/manifest digests, and the exact **OpenCode** target of that release policy. This target matches the runtime family used by this feature; another client's auth policy is never substituted. The snapshot also contains the original `plugin.json` and `mcp.json` bytes as strings and the MCP manifest SHA-256. All eligible package trees were verified against the Directory's `agentplugins-tree-sha256-v1` digest during extraction.

Cloudflare Docs and Firecrawl are supported because these exact target records explicitly say `not_required`, and their manifests define one HTTPS streamable HTTP server with no headers. Authentication metadata does not guarantee live availability, free or unlimited usage, or approval to use every exposed tool. Discovery and explicit tool approval remain mandatory. Every default-distribution MCP product appears, including unavailable entries with an explanation. The skills-only Agent Code Navigator is excluded. The highest active release sequence is selected when more than one active policy exists. Cloudflare Bindings is shown as unsupported because it requires auth with no compatible secret-header binding. Playwright, Docker Hub, Firebase and HubSpot Developer require local stdio and are unavailable. Context7's exact upstream default distribution points to its OAuth endpoint, with required auth and no secret-header mapping; it is unavailable. GitHub's default distribution has no OpenCode target, and Chrome DevTools is suspended. This pinned Directory does not contain DeepWiki or Microsoft Learn, so they are not presented as UAP presets.

The adapter accepts only exact `${ENV_NAME}` or `Bearer ${ENV_NAME}` header placeholders for required-auth remote packages, translating these into named dashboard-secret bindings. It never infers anonymous access from missing headers, and rejects unknown auth, OAuth/implicit auth, local launchers, ambiguous server sets, unsupported fields, and endpoint/header definitions rejected by the existing connection contract. No preset grants or guesses tool names. The server sends only the explicit public DTO to the client; raw manifests and hashing imports stay server-side. Existing connection validation, encryption, admin authorization and compare-and-swap writes remain authoritative.

## Updating

1. Review the intended immutable registry commit and each product/default distribution, active release policy, exact OpenCode target auth, and remote MCP manifests. Verify repository identity independently; the updater reads committed Git objects or explicit read-only GitHub API responses, and never runs registry code.
2. Run `node scripts/update-mcp-catalog.ts /absolute/path/to/registry FULL_40_CHARACTER_COMMIT_SHA --source=777genius/universal-agent-plugins=/absolute/path/to/legacy-packages --github`. Additional `--source=owner/repo=/absolute/checkout` arguments replace GitHub acquisition for that repository. `--github` permits read-only `gh api` acquisition of exact immutable tree/blob objects; it never executes their contents. Add `--check` to compare parsed snapshot values without writing it; outer JSON formatting is ignored while embedded raw manifest strings remain byte-exact. Format newly generated JSON with the repository formatter before committing. It reads only committed Git objects, ignoring dirty checkout files. It inventories all default-distribution MCP products, retains an explicit unavailable reason for suspended/no-target releases, selects the highest active sequence, and verifies each eligible package's manifest and complete package-tree digests. A null source revision resolves only to the immutable enclosing registry commit; other source repositories retain their exact published package SHA. It rejects symlinks, submodules, incomplete trees and invalid source locators.
3. Review the generated snapshot diff. Update the expected published-main pin in the contract test and this document together. The adapter and provenance links use the snapshot's pinned revision. Run `pnpm exec vitest run apps/web/src/server/mcp-catalog.test.ts` plus the relevant dashboard checks. Confirm unsupported packages remain unsupported and supported rows still require discovery/tool approval.

The snapshot is an application-reviewed extraction, not an assertion that a package is official, certified, activated or runtime-tested. It is not a universal Directory resolver or installer. Future registry changes require a reviewed application change; existing saved connections retain their own versioned definitions.

## Safe retry boundary and follow-up

The public Action forces OCR `attemptBudget=1` when model dispatch is enabled. Its ordinary OCR budget differs, but simply raising it replays an entire OCR process and may duplicate previously dispatched, billable calls. A request-level retry must instead use a fresh request identity and ordinal, consume the existing budget, and proceed only with a durable exact non-entry proof **and** separately acknowledged transport closure. No retry on `effect_unknown`, lost proof, active occupancy, stale authority or cancellation. Gateway currently records non-entry separately from closure; RR maps the rejected native effect to unknown and the current settlement proof describes local pre-forward non-entry. Gateway/RR/Action capability and proof plumbing plus fail-closed compatibility and real failure-injection tests are needed. See [attested request retry design](2026-11-27-attested-request-retry.md). This change would address confirmed non-entry only, not prove a fix for ambiguous streams or GitHub 403s.

## Reproduction and acceptance criteria

- Reproduce in disposable, network-isolated Gateway/native/PostgreSQL/Action fixtures using the same versioned producer capability, route and request budget. Inject: terminal non-entry with closure acknowledged; identical non-entry with closure withheld; 502 with no structured proof; stream loss after forward; an earlier successful OCR request followed by a rejection; lost or delayed settlement/readback; duplicate and foreign request proofs; stale lease, cancellation and concurrent claim. Reproduce GitHub 403 separately with mocked reset metadata and a revision change during wait. Preserve each case's observed state, receipt and exact source versions. Do not use customer PRs or real provider inference as fixtures.
- Accept a bounded retry only after the exact trusted request non-entry and closure receipts have been verified by the server, the prior dispatch has a durable terminal settlement, the existing request budget and deadline allow another request, and the same current execution/lease/fence remains valid. A fresh request ID and ordinal consume the original budget. Unknown effect, absent closure, ambiguous readback, stale execution, auth/invalid/quota failure and cancellation never retry. No replay of earlier OCR work; old producer and Gateway combinations remain fail-closed.
- For `required_review_coverage_incomplete`, verify that useful partial findings and accurate uncovered-file counts remain visible; a green complete result must never be emitted for missing required coverage. Do not increase token/time/request limits blindly to make checks pass.
- For GitHub rate limits, honor authoritative `Retry-After` or reset metadata within bounded execution time. If waiting outlives the review, require durable deferred retry with current-revision and previous-effect revalidation; do not keep a paid request or relay slot occupied.
- Require exact-source unit, real PostgreSQL concurrency and fault-injection tests, joined Gateway/native/Action E2E, independent security and compatibility review, CI and a staging canary. Update deployment registry for each affected repository/component. Roll out additive Gateway proof capability first, compatible RR verification next, then an explicitly qualified public Action release; only enable negotiated retry when all three are compatible. Retain old images and receipts. Rollback disables the new capability/consumer and preserves spent claims, native custody, unknown effects and partial results; never replay unknown dispatch.
